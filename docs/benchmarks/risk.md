## Protocol

For each repository and window, the last mainline commit at T is analyzed in a shared clone; its risk tiers use churn from the 90 days before T only. A file counts as **fixed later** when a non-merge commit of at most 50 files in the label window touched it and its subject matches `\b(fix|fixes|fixed|fixing|bug|bugs|bugfix|regression|hotfix)\b` (renames followed). Fix commits are a proxy for defects: they miss fixes described otherwise and count some that are not.

- **Check window:** T = HEAD − 360 days, labels from the next 180 days. No overlap with the data the thresholds were chosen on, so this is the test.
- **Exploration window:** T = HEAD − 180 days, labels up to HEAD. The "hot = 3 or more commits" threshold was chosen looking at this window (ADR-015); it is shown for reference, not as evidence.

The v1 score is the weighted percentile formula the tiers replaced, recomputed here only for comparison.

# Privacy and data flow

Epoch is local-first: your source code, the graph and the cache stay on your machine. There are no accounts, no hosted backend, no HTTP server and no telemetry. Epoch never modifies an analyzed project, and it never runs the project's code, scripts or configuration.

This page is the data-flow table that [CLAUDE.md](../CLAUDE.md) requires. Any new network call must be added here first.

## What leaves the machine

| Dead-feature detection (reachability, constants, git history) | Nothing                                                                          | On                  | Built                                                                                                                                                  |
| Heuristic scorer, co-change and shared-string hints           | Nothing                                                                          | On                  | Built                                                                                                                                                  |
| Embeddings similarity                                         | Nothing (a small local embedding model, bundled with the app; chosen in ADR-008) | On                  | Not built yet: the model is not bundled yet                                                                                                            |
| Local-model scorer and summaries (e.g. Ollama)                | Nothing (requests go to the model server on this machine)                        | Opt-in              | Scorer built for the CLI and benchmarks (`--scorer local`); summaries and the app's setting in M7                                                      |
| Jev scorer                                                    | Code snippets and context sent to TypeSafe AI                                    | Opt-in              | Not built: its docs could not be read                                                                                                                  |
| LLM summaries and LLM scorer                                  | File source and neighbor summaries sent to the model provider                    | Opt-in              | Scorer built for the CLI and benchmarks (`--scorer llm`, with your key, `--consent-send` and `--max-spend`); summaries, the app and offline mode in M7 |
| Update check                                                  | A request to the release host for the latest version. No project data            | On; can be disabled | Not built yet (M8)                                                                                                                                     |

With no keys configured and update checks disabled, Epoch makes no network requests. Today the desktop app has no network feature at all (a test checks that its build carries no model client), and the CLI sends something only when you pass `--scorer local` (to the Ollama server on this machine) or `--scorer llm` with `--consent-send`. The automated test that runs a full analysis with the network blocked arrives with offline mode (M7).

## Notes

- **Git.** Epoch runs `git` on your machine to read history (churn, co-change, when a line last changed). It only reads commits that are already there and never fetches. It runs read-only commands with the fsmonitor hook, signature checks, external diff and text-conversion drivers and the pager turned off, so a repository's own git configuration cannot make it run anything.
- **Hints.** Co-change and shared-string hints are computed on your machine from your git history and the files' own key-like strings. The cache keeps those short strings (event names, routes, keys), never file contents.
- **The embedding model will be downloaded when Epoch is built, not when it runs.** The build will fetch a pinned model revision and check its hash, and the installer will carry the model, so the installed app never downloads it. If the model is missing, similarity hints are simply off (as they are today).
- **Remote models are off by default.** `epoch analyze` and `epoch findings` use one only with `--scorer llm` and your own key in `ANTHROPIC_API_KEY`. Without `--consent-send`, Epoch prints exactly what it would send (which files, how many characters of each, the co-change counts and shared strings, the estimated tokens and the most it could cost at your prices) and sends nothing. With it, Epoch sends at most `--max-pairs` file pairs and stops before a request could pass `--max-spend`. It never sends files that look like secrets (`.env*`, keys, credentials), even with consent.
- **One door out.** Every scorer request goes through one network module (`packages/scorers/src/net.ts`) that sends only to the provider's own address (`https://api.anthropic.com` or `http://127.0.0.1:11434`) and refuses everything in offline mode. Your key goes only to Anthropic: the address is fixed, not read from the environment. A lint rule flags network calls written anywhere else in Epoch's own code; it is a backstop, and M7's zero-network test is the proof. Offline mode will block every outbound request (M7).
- **Exports are explicit.** Sharing means writing a file you choose and sharing it yourself.

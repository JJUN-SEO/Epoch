# Privacy and data flow

Epoch is local-first: your source code, the graph and the cache stay on your machine. There are no accounts, no hosted backend, no HTTP server and no telemetry. Epoch never modifies an analyzed project, and it never runs the project's code, scripts or configuration.

This page is the data-flow table that [CLAUDE.md](../CLAUDE.md) requires. Any new network call must be added here first.

With no keys configured and update checks disabled, Epoch makes no network requests. In the app only the main process sends, and only summary requests, through one Electron session that allows nothing but Anthropic's API and the local model server; the analysis host and its parse workers refuse any network use, and so does main's own Node runtime.

**Offline mode** (Settings → Privacy in the app, `--offline` in the CLI) refuses every request, read at each request and cancelling any in flight, except to a local model you chose (loopback only, nothing leaves the machine). Automated tests prove it: the CLI runs a full analysis with every network function replaced by a recorder and must make zero attempts (in the tests on every OS, and on Linux again inside a network namespace with no network at all); the app's e2e test reads Chromium's own network log during a full analysis and a summary attempt with offline mode on and finds no request, after a canary shows the log does see one.

## Notes

- **Git.** Epoch runs `git` on your machine to read history (churn, co-change, when a line last changed). It only reads commits that are already there and never fetches. It runs read-only commands with the fsmonitor hook, signature checks, external diff and text-conversion drivers and the pager turned off, so a repository's own git configuration cannot make it run anything.
- **Hints.** Co-change and shared-string hints are computed on your machine from your git history and the files' own key-like strings. The cache keeps those short strings (event names, routes, keys), never file contents.
- **The embedding model is downloaded when Epoch is built, not when it runs.** `scripts/fetch-model.mjs` (run by CI) fetches a pinned model revision from Hugging Face and checks every file's sha256, and the installer carries the model, so the installed app never downloads it. The model runs in the analysis host on your CPU; what it computes (vectors, numbers only) stays in the local cache. Without the model, or with `EPOCH_EMBEDDING_MODEL=off`, similarity hints are off. The CLI uses a model only when you name its folder with `--embedding-model`.
- **Remote models are off by default.** In the app, summaries are off until you save an Anthropic key or turn them on. Before the first summary of a project goes to Anthropic, main asks in its own dialog, listing the files and the most it can cost; the renderer cannot approve a send. A summary is made by itself only when you open a file (for Anthropic, after that consent), and only when its worst case is under your ask-first amount and both budgets; anything bigger (and every folder) waits for you to approve it. In the CLI, `epoch analyze` and `epoch findings` use a model only with `--scorer llm` and your own key: without `--consent-send`, Epoch prints exactly what it would send (which files, how many characters of each, the co-change counts and shared strings, the estimated tokens and the most it could cost at your prices) and sends nothing; with it, Epoch sends at most `--max-pairs` file pairs and stops before a request could pass `--max-spend`. Files that look like secrets (`.env*`, keys, credentials, or content with a private key) are never sent, even with consent.
- **Spending.** Epoch ships the default model's price, copied from Anthropic's pricing page with the date it was read; you can replace it, and you enter the price of any other model. Paid requests stop at a monthly cap ($5 unless you change it) and a budget per session ($1). Each request reserves its worst case before it is sent and settles at the usage the provider reports, so requests together cannot pass the cap. Raising a limit or resetting the month is confirmed in main's own dialog. The spend record holds counts and dollars only, no paths or content.
- **Summaries stay on this machine.** They are cached in Epoch's local cache, keyed by what was sent, so an unchanged file is never sent again, even after a restart. The cache keeps no source: code blocks and any sentence that repeats a line of the file are dropped before a summary is stored. Settings shows how many summaries the cache holds and how many were paid for, and Clear says so before it deletes them.
- **Keys.** You supply your own; Epoch never pays for, proxies or sees model usage. In the app the key is sent once to main and encrypted with your system's protection (Electron `safeStorage`); on Linux without a keyring Epoch warns and keeps it for the session unless you choose weak storage. The window only ever learns whether a key is set. In the CLI, `epoch auth set anthropic` stores it in the OS keychain, or set `ANTHROPIC_API_KEY` (ADR-009); a key is never read from the command line. Keys never go into the cache, logs, error messages or exports: an automated test enters a key, has it refused once and used once, then scans every file Epoch and Chromium wrote, everything the app printed, the window and its storage, and every answer it gave, and finds the key only as ciphertext in the key file (on Linux and Windows; on macOS the keychain may prompt on a CI runner, so that test is skipped there).
- **One door out.** Every model request goes through one network module (`packages/scorers/src/net.ts`) that sends only to the provider's own address (`https://api.anthropic.com` or `http://127.0.0.1:11434`) and refuses everything in offline mode; in the app it runs over main's dedicated session, whose own request filter allows the same two addresses. Your key goes only to Anthropic: the address is fixed, not read from the environment. Lint rules flag network calls, and Electron's network APIs, written anywhere else in Epoch's own code; the tests above are the proof.
- **Exports are explicit.** Sharing means writing a file you choose and sharing it yourself.
